# 🚚 ZapShift — Parcel Delivery Server

This is the backend REST API for **ZapShift**, a parcel delivery management application.

The server handles users, riders, parcels, payments, tracking, authentication, and delivery management.

## 🌐 API Server

**Production API:**

https://zap-shift-server-five-theta.vercel.app/

## 🔗 Client Repository

**Frontend:** https://github.com/mufassir-mahmud/zap-shift-client

---

## ✨ Features

### 👤 User Management

* Create users
* Find users
* Search users
* Get user role
* Update user role
* Admin role management
* Rider role management

### 🚴 Rider Management

* Submit rider application
* View riders
* Filter riders by:

  * Status
  * District
  * Work status
* Approve rider
* Reject rider
* Delete rider
* Update rider work status
* Track rider delivery statistics

### 📦 Parcel Management

* Create parcels
* Generate unique tracking IDs
* Get parcels
* Get parcel by ID
* Filter parcels by sender email
* Filter parcels by delivery status
* Assign rider to parcel
* Update parcel delivery status
* Delete parcels
* Generate delivery status statistics

### 📍 Tracking System

Every parcel receives a unique tracking ID.

Example:

```text
TRK-260928-A1B2
```

Tracking events include:

```text
parcel-created
pending-pickup
driver-assigned
parcel-delivered
```

Each tracking record contains:

* Tracking ID
* Status
* Details
* Created date

### 💳 Stripe Payment

The backend creates Stripe Checkout sessions and processes successful payments.

Payment flow:

```text
Client
  ↓
Create Checkout Session
  ↓
Stripe
  ↓
Successful Payment
  ↓
/payment-success
  ↓
Update Parcel
  ↓
Save Payment
  ↓
Create Tracking Log
```

## 🔐 Authentication & Authorization

Firebase Admin SDK is used to verify Firebase ID tokens.

Protected requests use:

```http
Authorization: Bearer <firebase-id-token>
```

The server verifies the token and extracts the authenticated user's email.

Admin-only routes additionally check the user's role in MongoDB.

Authorization flow:

```text
Client
  ↓
Firebase Login
  ↓
Firebase ID Token
  ↓
Authorization Header
  ↓
Firebase Admin Verification
  ↓
User Role Verification
  ↓
Protected API
```

## ⚙️ Installation

Clone the repository:

```bash
git clone https://github.com/mufassir-mahmud/zap-shift-server.git
```

Go to the server directory:

```bash
cd zap-shift-server
```

Install dependencies:

```bash
npm install
```

Create a `.env` file:

```env
DB_USER=your_mongodb_username
DB_PASS=your_mongodb_password

FB_SERVICE_KEY=your_base64_encoded_firebase_service_account

STRIPE_SECRET=your_stripe_secret_key

SITE_DOMAIN=http://localhost:5173

PORT=3000
```

Start the server:

```bash
node index.js
```

For development with Nodemon:

```bash
nodemon index.js
```

The local API will run at:

```text
http://localhost:3000
```

## 🔑 Environment Variables

| Variable         | Description                                   |
| ---------------- | --------------------------------------------- |
| `DB_USER`        | MongoDB username                              |
| `DB_PASS`        | MongoDB password                              |
| `FB_SERVICE_KEY` | Base64 encoded Firebase Admin service account |
| `STRIPE_SECRET`  | Stripe secret key                             |
| `SITE_DOMAIN`    | Frontend URL used by Stripe                   |
| `PORT`           | Local server port                             |

**Never commit `.env` or Firebase service-account credentials to GitHub.**

## 📡 Main API Endpoints

### Users

```http
GET /users
POST /users
GET /users/:id
GET /users/:email/role
PATCH /users/:id/role
```

### Riders

```http
GET /riders
POST /riders
PATCH /riders/:id
DELETE /riders/:id
GET /riders/delivery-per-day
```

### Parcels

```http
GET /parcels
POST /parcels
GET /parcels/:id
PATCH /parcels/:id
PATCH /parcels/:id/status
DELETE /parcels/:id
GET /parcels/rider
GET /parcels/delivery-status/stats
```

### Payments

```http
POST /create-checkout-session
PATCH /payment-success
GET /payments
```

### Tracking

```http
GET /trackings/:trackingId/logs
```

## 🗄️ MongoDB Collections

The application uses the following collections:

```text
zap-shif-client
│
├── users
├── riders
├── parcel
├── payments
└── trackings
```

### Users

Stores:

* Name
* Email
* Role
* Created date

Possible roles:

```text
user
rider
admin
```

### Riders

Stores rider information such as:

* Rider name
* Email
* District
* Status
* Work status

Possible rider statuses:

```text
pending
approved
rejected
```

Possible work statuses:

```text
available
in-delivery
unavailable
```

### Parcels

Stores:

* Parcel information
* Sender information
* Delivery information
* Price
* Payment status
* Delivery status
* Tracking ID
* Rider information

### Payments

Stores:

* Amount
* Currency
* Customer email
* Parcel ID
* Transaction ID
* Payment status
* Tracking ID
* Payment date

### Trackings

Stores:

* Tracking ID
* Delivery status
* Status details
* Created date

## 🚀 Deployment

The backend is deployed on Vercel.

Production deployment:

```bash
vercel --prod
```

The project uses `vercel.json` to configure the Express server:

```json
{
  "version": 2,
  "builds": [
    {
      "src": "index.js",
      "use": "@vercel/node"
    }
  ],
  "routes": [
    {
      "src": "/(.*)",
      "dest": "index.js"
    }
  ]
}
```

## 🔒 Security

Sensitive information is stored using environment variables.

The following should **never** be committed to GitHub:

```text
.env
Firebase service account JSON
Stripe secret key
MongoDB password
```

Example `.gitignore`:

```text
node_modules/
.env
.vercel/
*.json
```

If a Firebase service-account JSON file is required locally, keep it outside Git tracking and use an environment variable for deployment.
